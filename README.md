# Kelly Peterson For Texas

Official campaign website for **Kelly Peterson, Republican candidate for Texas State Representative, District 126**.

This is a static site built with [Hugo](https://gohugo.io/) (extended) and deployed via [Netlify](https://www.netlify.com/). The site is content-driven: most editing happens in markdown files under `content/` rather than in templates.

- **Production URL:** https://kellypetersonfortexas.com/
- **Hosting:** Netlify (auto-deploys from the connected Git branch)
- **Form handler:** [Basin](https://usebasin.com/) (two endpoints — general contact + volunteer)
- **Donations:** [WinRed](https://winred.com/) (external link, not handled on-site)

---

## Tech Stack

| Layer | Tool |
|---|---|
| Static site generator | Hugo Extended **v0.141.0** (production) / **v0.145.0** (local, see `.tool-versions`) |
| CSS framework | Bootstrap **5.1.3** (customized + minified, in `assets/css/`) |
| JS libraries | Magnific Popup, AOS (Animate on Scroll), Owl Carousel, lazysizes |

> **Hugo Extended is required.** The standard Hugo build will fail on SCSS/asset pipeline operations. Install via the [Hugo releases page](https://github.com/gohugoio/hugo/releases/) or use `asdf` with the included `.tool-versions` file.

## Local Development

### Prerequisites

- Hugo Extended **>= v0.108.0** (Netlify uses **v0.141.0** — match this to avoid build surprises)
- Git
- (Optional) [`asdf`](https://asdf-vm.com/) — `.tool-versions` is included so `asdf install` will pick up the right Hugo version

### Run a local dev server

```bash
hugo serve
```

Then open `http://localhost:1313/` in your browser. Hugo will live-reload on file changes.

### Useful flags

```bash
# Include draft + future-dated content (matches Netlify's deploy-preview build)
hugo serve -D --buildFuture

# Bind to all interfaces (useful for testing on a phone over LAN)
hugo serve --bind 0.0.0.0 --baseURL http://<your-local-ip>:1313
```

### Production build (matches Netlify exactly)

```bash
hugo --gc --minify && cp robots.production.txt public/robots.txt
```

Output is written to `public/`. This directory is **gitignored** — Netlify generates it on each deploy.

### Staging / preview build

```bash
hugo --gc --buildFuture && cp robots.staging.txt public/robots.txt
```

The staging `robots.txt` blocks all crawlers (`Disallow: /`) so preview deploys don't get indexed.

## Content Editing Cheat Sheet

### Update homepage hero / banner

Edit `content/_index.md`:

```yaml
---
banner_title: Proven leadership. Conservative results.
banner_tagline: Endorsed by <strong>State Rep. Sam Harless!</strong>
banner_image: /img/banner.png
candidate_image: /img/kelly-peterson.png
# banner_video: W9as7QP8GkM   # Uncomment to swap banner image for a YouTube embed
sections: "home"               # Must match section_categories in content/sections/*.md
---
```

### Add or edit a homepage section

Sections are markdown files in `content/sections/`. Each has frontmatter that controls how it's rendered:

```yaml
---
title: Section Title
weight: 1                                     # Display order (lower = earlier)
id: section-id                                # HTML anchor for #linking
position: justify-content-end align-content-center   # Bootstrap flex utility classes
size: col-12 col-md-7                         # Bootstrap column sizing
image: /img/background.jpg                    # Optional background image
section_image: /img/inline.jpg                # Optional inline image
section_categories:
    - Home                                    # Must match `sections` value in _index.md
---

Body content here in markdown.
```

The `page-sections.html` partial filters sections by matching the page's `sections` parameter against the `section_categories` taxonomy — that's how the homepage decides which sections to show.

### Add a news post

Drop a markdown file into `content/news/`. See `content/news/sample_onsite.md` and `sample_outbound.md` for examples (an inbound article vs. a link to an external article).

### Update site-wide config

`config.yaml` controls:

- **Social links** — `twitter_link`, `facebook_link`, `instagram_link` (commented out by default)
- **Form endpoints** — `form_endpoint` (general) and `form_endpoint_volunteer` (Basin URLs)
- **Donate button** — `donate_link` (WinRed) and `donate_link_label`
- **"Paid for" disclaimer** — `paid_for`
- **Main navigation menu** — `menu.main` array
- **Google Tag Manager** — `gtm` (currently commented out — uncomment + supply ID to enable)

> ⚠️ The `baseURL` line at the top of `config.yaml` is currently commented out. Netlify supplies the URL via its environment, but if you build for any non-Netlify host, set this explicitly.

## Deployment (Netlify)

The site is deployed via Netlify and configured in `netlify.toml`. You shouldn't need to run any deploy commands manually — every push to the connected branch triggers a build.

### Build contexts

| Context | Command | Robots |
|---|---|---|
| `production` | `hugo --gc --minify` | `robots.production.txt` (allow all, disallow `/thank-you/`) |
| `deploy-preview` | `hugo --gc --buildFuture` | `robots.staging.txt` (disallow all) |
| `branch-deploy` | `hugo --gc --buildFuture` | `robots.staging.txt` (disallow all) |

### Environment variables (set in `netlify.toml`)

- `HUGO_VERSION = "0.141.0"` — pin this when upgrading
- `HUGO_ENV = "production"`
- `HUGO_ENABLEGITINFO = "true"` — exposes git commit info to templates
- `HUGO_BUILD_DRAFTS` / `HUGO_BUILD_FUTURE` / `HUGO_BUILD_EXPIRED` — control which content is rendered per context

### Connecting a fresh Netlify site

1. Push the repo to GitHub (or GitLab / Bitbucket).
2. In Netlify: **Add new site → Import an existing project →** select the repo.
3. Netlify reads `netlify.toml` and uses the build command + publish directory automatically. **Do not override** the build command in the Netlify UI — it should remain blank so `netlify.toml` is the source of truth.
4. Configure the custom domain (`kellypetersonfortexas.com`) under **Domain settings**.
5. Verify SSL is provisioned (Netlify handles Let's Encrypt automatically).
6. Trigger an initial deploy.

### Form endpoints (Basin)

Forms post directly to Basin from the browser. To rotate or replace the endpoints:

1. Create the form(s) in your Basin account.
2. Update `form_endpoint` and `form_endpoint_volunteer` in `config.yaml`.
3. Commit + push — Netlify will redeploy.

### Donations (WinRed)

The donate button is a link to `donate_link` in `config.yaml`. There is no on-site checkout — all donation processing happens on WinRed.

## Optional / Disabled Features

A few things are scaffolded but turned off. Re-enable as needed:

- **NetlifyCMS** — `static/admin/` contains `config.yml` and `index.html`. Enable by linking the repo in Netlify Identity + Git Gateway, then ensure `/admin/` is reachable. Currently the integration is unconfigured; treat it as a starting point, not a working CMS.

- **Instagram link** — uncomment `instagram_link` in `config.yaml` once an account exists.
- **Banner video** — uncomment `banner_video` in `content/_index.md` and provide a YouTube ID to swap the hero image for a video.

## Notes for Vendors / Handoff

- **Source of truth for build config is `netlify.toml`.** Don't duplicate settings in the Netlify UI.
- **Hugo version drift** is the most common build break. Match `HUGO_VERSION` in `netlify.toml` and `hugo extended_*` in `.tool-versions` when upgrading.
- **`public/` and `resources/` are gitignored** — never commit build output.
- **Images** live in `static/img/` and are referenced from content as `/img/foo.jpg`. The `netlify-plugin-image-optim` build plugin compresses them at deploy time, so commit reasonable-sized originals (it won't fix 10MB hero images well — pre-optimize first).
- **Lazy loading** uses `lazysizes` — image tags should use `class="lazyload"` and `data-src="..."` instead of `src="..."`. See existing partials for examples.
- **`CLAUDE.md`** documents conventions for AI coding assistants and is a useful quick reference for humans too.

## Troubleshooting

- **Build fails with SCSS / `resources.ToCSS` errors** → you're not on Hugo *Extended*. Reinstall the extended build.
- **Local `hugo serve` works, Netlify build fails** → check Hugo versions match (`netlify.toml` vs. local `hugo version`).
- **Forms silently don't submit** → confirm Basin endpoints in `config.yaml` are correct and the Basin account is active.
- **Preview deploys appearing in Google** → confirm `robots.staging.txt` was copied to `public/robots.txt` during the staging build (`netlify.toml` handles this — don't remove the `cp` step from the build command).
- **Stale styles / JS after deploy** → Hugo fingerprints assets, so this usually means a cached HTML page. Hard-refresh or check Netlify cache headers.
